## Chapter 5: Blob, Files, and Data Movement Tools — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Archive tier minimum storage duration before early deletion fee applies? | 180 days. Exam tip: Archive = cheapest, offline storage; rehydration required before read access (Standard priority up to 15 hrs, High priority under 1 hr for blobs <10GB). |
| 2 | Cool tier vs Cold tier minimum storage duration? | Cool = 30 days. Cold = 90 days. Early deletion before the minimum incurs a prorated fee. Exam tip: order from cheapest access-frequency assumption to most frequent: Archive > Cold > Cool > Hot. |
| 3 | Object replication prerequisites (all 4)? | 1) Blob versioning enabled on source AND destination, 2) Change feed enabled on source, 3) Block blobs only (no page/append blobs), 4) GPv2 or premium block blob accounts, source ≠ destination account. |
| 4 | Azure Files: SMB vs NFS 4.1 — key exam differentiator? | SMB: any tier (standard/premium), Windows-style ACLs, works over public endpoint with firewall rules. NFS 4.1: Premium (FileStorage) accounts ONLY, requires private endpoint/VNet (no public access), POSIX permissions, no AD auth, no soft delete/snapshots on some features. |
| 5 | Container access levels: Private vs Blob vs Container? | Private: no anonymous access. Blob: anonymous read of individual blobs by URL only (no listing). Container: anonymous read of blobs AND container listing. Exam tip: default for new containers is Private. |
| 6 | Azure File Sync topology components? | Storage Sync Service (Azure resource) → Sync Group → one Cloud Endpoint (an Azure file share) + one or more Server Endpoints (a path on a registered Windows Server). Cloud tiering caches hot files locally and replaces cold files with pointers (reparse points). |
| 7 | AzCopy: mirror local folder to blob container, deleting extras at destination? | azcopy sync <source> <destination> --delete-destination=true. Exam tip: azcopy copy never deletes; only azcopy sync supports true mirroring. |
| 8 | Time-based retention immutability policy — locked policy extension rule? | Retention period can only be INCREASED, never decreased, once locked. Extension is allowed a maximum of 5 times. Legal hold has no fixed period and is removed manually. |
| 9 | Standard vs Premium Azure file share max size? | Standard file share: 5 TiB default, up to 100 TiB with 'large file shares' enabled. Premium (FileStorage) file share: up to 100 TiB baseline. Exam tip: large file shares can't be reverted once enabled on standard GPv2. |
| 10 | Storage account firewall default behavior when a virtual network rule is added? | Adding any network rule automatically sets default action to Deny for public traffic; only allowed IPs/VNets (or 'trusted Microsoft services' exception) can access. Exam tip: trusted services bypass (e.g., Azure Backup) must be explicitly checked. |
| 11 | When to choose Azure Storage Explorer vs AzCopy? | Storage Explorer: GUI tool, ad-hoc browsing/management, good for small manual operations, supports Blob/Files/Queues/Tables. AzCopy: CLI tool, optimized for large-scale/high-throughput copy, sync, and migration jobs — exam favors AzCopy for bulk data movement scenarios. |
| 12 | Max block blob size and max number of blocks (uncommitted)? | Max block blob size: ~190.7 TiB. Max blocks per blob: 50,000. Max block size: up to 4000 MiB (4 GiB) with newer service versions. Exam tip: relevant when troubleshooting large AzCopy uploads. |
