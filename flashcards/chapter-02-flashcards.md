## Chapter 2: Azure RBAC: Roles, Scopes, and Assignments — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Max custom roles allowed per Microsoft Entra tenant? | 5000. Exam tip: this limit is shared across all subscriptions in the tenant, not per-subscription. |
| 2 | Max Azure RBAC role assignments per subscription? | 4000. Exam tip: if you approach this limit, assign roles to groups instead of individual users to cut down the total count. |
| 3 | Owner vs Contributor — key difference? | Owner = full resource management + can assign roles (manage access). Contributor = full resource management but CANNOT assign roles. Exam tip: 'can create/delete resources but not grant access' = Contributor. |
| 4 | Contributor vs User Access Administrator? | Contributor manages resources but not access. User Access Administrator manages role assignments but has no permission to manage resources themselves. Exam tip: assign both (or Owner) if a user needs to do both. |
| 5 | Azure RBAC vs Azure Policy — what's the distinction? | RBAC = controls WHO can perform WHAT actions (authorization). Policy = enforces resource configuration/compliance rules regardless of who acts. Exam tip: 'enforce tagging' or 'require encryption' = Policy, not RBAC. |
| 6 | Azure RBAC vs Microsoft Entra ID roles? | Azure RBAC controls access to Azure resources (VMs, storage, networking via ARM). Entra ID roles control access to directory objects (users, groups, apps, licenses). Exam tip: managing users/groups requires an Entra role (e.g., User Administrator), not Azure RBAC. |
| 7 | RBAC scope inheritance order (top to bottom)? | Management Group → Subscription → Resource Group → Resource. Permissions flow DOWN only. Exam tip: a Resource Group-level assignment has no effect on the parent Subscription. |
| 8 | User has Reader at Subscription scope and Contributor at a child Resource Group. Effective permission on that Resource Group? | Contributor. RBAC assignments are additive across scopes — the union of grants applies, and the more permissive role always wins. There's no override, only accumulation. |
| 9 | Custom role JSON — core properties? | Name, IsCustom, Description, Actions, NotActions, DataActions, NotDataActions, AssignableScopes. Exam tip: AssignableScopes cannot be left as '/' — it must list specific management groups, subscriptions, or resource groups. |
| 10 | Azure CLI command to create a custom role from a JSON file? | az role definition create --role-definition customrole.json. Exam tip: to modify an existing custom role, use az role definition update with the same JSON, including its 'id' field. |
| 11 | Deny assignments vs role assignments? | Role assignments GRANT access; deny assignments explicitly BLOCK access and always take precedence over any role assignment. Exam tip: regular admins can't manually create deny assignments — they're generated by Azure Blueprints, managed apps, or system identities. |
| 12 | Does NotActions in a custom role act as an explicit deny across all roles a user holds? | No. NotActions only subtracts from the Actions granted by that SAME role definition. If the user has another role assignment granting that action, they still have it. Exam trap: NotActions ≠ deny assignment. |
